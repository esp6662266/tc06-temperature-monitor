- 실제 TV 청취, 실제 Windows 설치·캡처·EXE 실행은 이번 개발 환경에서 확인하지 않았다.

## 운영 배포·삭제 확인

- 운영 URL: https://tc06-temperature-monitor.netlify.app/ 및 `?mode=normal`.
- 온도 전용 Site ID: `67ba3ef2-67cd-4fdb-afdb-bd303748108c`.
- v0.4 배포 ID: `6ad0f9c93c330ce5ad19e192`. 그래프 주소: https://tc06-temperature-monitor.netlify.app/?mode=graph
- 이전 v0.3 배포 ID: `6ad0f3205d7efde452d83dae`.
- Netlify 관리 API에서 `cleanup` 함수의 예약 `15 * * * *` 등록을 확인했다. 실제 런타임 메타데이터는 Node.js 24다.
- 실제 Netlify Blobs에서 자신이 만든 만료 진단 기록 1개·최근 날짜 진단 기록 1개·이전 음성 형식 진단 키 1개로 정리 함수를 실행했다. 만료 기록과 음성만 삭제되고 최근 기록은 남는 것을 다시 조회해 확인했다. 남긴 진단 키도 직접 정리했고 최신값은 null로 유지했다. 실제 정상 온도 시험값을 운영 이력에 넣지 않았다.
- 이 검사는 정리 코어를 인증된 SDK로 실제 저장소에 실행한 결과다. Netlify 시계가 예약 함수를 자동으로 첫 호출한 로그까지 확인했다는 의미는 아니다. `/api/retention`의 최근 결과와 관리 화면 로그로 이후 예약 실행을 확인할 수 있다.
- 운영 HTTPS 페이지에서 OS speechSynthesis를 비활성화한 Chrome으로 17개 MP3 디코딩·38도 조합·실행 중인 Web Audio를 확인했다. 서비스 워커 준비 후 오프라인 재접속에서도 같은 조합이 재생됐고 페이지 오류는 없었다.
- 30일은 한국 날짜 기준 오늘 포함 30개 날짜다. 물리 삭제는 매시 15분이며 한도 초과는 다음 실행에서 계속한다. 만료 조회·재수신은 즉시 거부한다. PC SQLite 이력은 별도 유지한다.
- 이전 v0.2에서는 운영 공개 POST로 진단 상태(null 온도)를 저장하고 최신값/CSV에서 재조회한 뒤 시험 키를 정리한 바 있다.

## 알려진 OCR 한계

사용자 제공 정지 이미지에서 TC-06 라벨과 표시 숫자가 일치하는 판독을 확인했다. 정지 이미지이므로 정상 현재값으로 서버 전송하지 않았고 원본은 공개 저장소에 넣지 않았다.

v0.4의 합성 글꼴 시험에서 350.0을 550.0으로 오독하고 999.9를 못 읽는 사례가 확인됐다. v0.4.1은 해당 합성 사례를 개선했지만 같은 엔진의 두 분할 방식이 동시에 틀릴 가능성이 남아 있다. 전체 백 단위 정확도나 실제 HMI의 백 단위 검증 완료를 주장하지 않는다. 붙은 숫자·흐림·작은 글씨를 더 보수적으로 보류해 미인식이 늘어날 수 있으며 실제 HMI 글꼴·해상도에서 교차 검증이 필요하다.
