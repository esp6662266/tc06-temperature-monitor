# OCR 보완 · v0.4.1

검사일: 2026-10-16 한국시간. 아래 수치는 개발용 합성 영상의 회귀 결과이며 실제 설비 정확도나 오독 없는 동작의 보장이 아니다. 원본 운전 화면·온도 이력은 공개 저장소에 포함하지 않는다.

## 판독 절차

1. 지정 영상 안의 TC-06 라벨과 오른쪽 회색 칸을 찾고 가림 여부를 검사한다.
2. 숫자의 회색조 가장자리를 보존하고 배경을 정규화한다. 원본 경계에 글자가 닿거나 대비가 부족하면 보류한다.
3. 숫자 영역에 밝은 여백을 두고 2배 확대/줄 분할(`psm 7`)과 4배 확대/원시 줄 분할(`psm 13`)로 각각 읽는다. 사전을 끄고 숫자·마침표·마이너스만 허용한다.
4. 두 **문자열 전체**가 일치하고 각각 점수가 60 이상이어야 한다. 문자열은 정수부 1~4자리·소수점 아래 1자리만 허용한다. 두 방식은 같은 Tesseract 엔진이며 독립된 두 엔진이라고 주장하지 않는다.
5. 원본 픽셀에서 큰 글자 덩어리 수·세로 정렬·소수점 위치를 대조한다. 소수점이 마지막 숫자에 붙는 작은 HMI 글꼴도 검사한다. 붙은 정수 숫자를 확실히 나눌 수 없으면 보류한다.
6. 원본 시계 진행 확인 후 시작/복구에는 다음 원본 시계 진행에서 근접한 판독을 한 번 더 요구한다. 첫 화면은 시계 미확인, 두 번째는 추가 확인 중, 세 번째에서 확인될 수 있다.
7. 마지막 확인값과 차이가 `max(5도, 마지막 값 절댓값의 2%)`를 넘으면 다음 원본 시계 진행에서 다시 확인한다. 이것은 물리적 온도 변화율/상한이 아닌 일시적인 튐 검사의 기준이다. 실제 900→1200 변화도 새 값 근처에서 확인되면 그대로 보낸다. 계속 빠르게 변하는 동안에는 확인이 지연될 수 있다.

확인에 쓰는 두 값이 근접한지 비교할 뿐 평균을 내지 않으며, 확정 시에는 **현재 프레임의 값**을 보낸다. 실패·가림·원본 시계 미확인/정지·연결 예외·15초 초과 관측 공백 뒤에는 다시 확인한다. 미확인 값은 `value_suspect` 등 상태와 null로 기록하며, 이전값이나 기본 38도로 정상 온도 기록을 만들지 않는다. 숫자/음성 웹의 기본값 38도 정책은 기존과 같다.

전처리의 근거는 [Tesseract 공식 품질 문서](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)의 밝은 배경·적절한 여백/확대·영역별 분할·숫자 사전 비활성화 지침이다. 실제 입력 글꼴/압축에 맞는 현장 검증은 별도로 필요하다.

## 확인한 결과

동일한 OpenCV 합성 화면 15개를 v0.4(`c0de523`)와 v0.4.1에서 같은 Tesseract 5.5.3으로 비교했다. 이는 정지 화면의 후보 판독 검사이며 서버 업로드 시험이 아니다.

| 38.0 | 58.0 오독 | 38.0 |

| 550.0 | 950.0 오독 | 550.0 |
| 999.9 | 판독 실패 | 999.9 |
| 900.0 / 901.2 / 950.0 / 980.8 / 1000.0 | 올바른 후보 | 올바른 후보 |
| 1234.5 | 올바른 후보 | 붙은 3·4 때문에 보류 |

표본 15개는 0.0, 38.0, 100.0, 123.4, 350.0, 550.0, 600.0, 800.0, 900.0, 901.2, 950.0, 980.8, 999.9, 1000.0, 1234.5다.

추가 시험:

- 900~999 정수부 각각에 끝자리와 같은 소수부를 붙인 합성 숫자 100개: **92개 올바른 판독 / 8개 보류 / 잘못 통과한 값 0개**. 900.0·901.1·…·999.9만 검사했으며 모든 소수점 조합 검사가 아니다.
- 숫자 9종 × 원본/75% 축소/가우시안 흐림/JPEG 품질50, 36개: **13개 올바른 판독 / 23개 보류 / 잘못 통과한 값 0개**. 원본에서도 붙은 글자는 보류한다. 흐린 화면의 높은 판독 성공률을 주장하지 않는다.
- 900.0·999.9·1000.0 합성 영상은 시계 진행과 추가 판독 확인 후 정상값이 된다. 한 번의 급격한 낮은 값은 보류하고, 지속되는 1200도 변화는 확인 후 수용하는 시간 순서 시험을 포함한다.
- 두 모드 불일치, 양쪽 OCR에서 동일하게 앞자리 누락, 소수점 오류, 낮은 점수, 잘린 영역, 실제 소수점 제거, 가림/라벨 누락, 재연결은 정상 온도로 통과하지 않는 회귀 시험이 있다.
- 사용자 제공 정지 이미지의 표시와 후보를 로컬에서 대조했다. 서버 전송·현재 운전 확인·백 단위 실기 검증으로 취급하지 않았고 원본을 커밋하지 않았다.

시험 조건: macOS, Python 3.9.6, Tesseract 5.5.3, OpenCV 5.0.0.93. 다른 Tesseract 학습 데이터/버전과 실제 Windows 입력은 결과가 달라질 수 있다. 점수 60은 Tesseract의 출력 점수이며 정확도 확률이 아니다.

```powershell
python -m pytest -q
python -m pytest -q -s tests/test_ocr_stress.py
```

## 실제 Windows에서 적용·검증

수집기를 중지하고 로컬 수정 보존 여부를 확인한 뒤 최신 저장소를 받는다. 소스 실행은 재시작, 기존 EXE는 Windows에서 재빌드/실행 검증이 필요하다. 서버나 웹만 갱신해도 OCR이 개선되는 것은 아니다. 추가 AI API·음성 설치·서버 인증 설정은 필요 없다.

현장에서는 캡처보드 원본 해상도를 유지하고 축소·무선 압축·흐림을 줄인 상태에서 실제 HMI의 각 숫자와 GUI 판독을 대조한다. 판독 불가가 잦으면 숫자가 충분히 크게 캡처되는지 먼저 확인한다. 이 프로그램이 HMI 창을 움직이거나 운전을 변경하지는 않는다.

900도 이상·1000도 이상·소수점·빠른 변화·창 이동/축소·가림·네트워크 복구를 별도로 확인한다. 실제 고온 장면이 아직 없으면 그 항목을 미확인으로 남긴다. 실제 숫자를 두 방식이 똑같이 잘못 읽는 경우는 여전히 가능하다. 확인 전에는 보호/인터록/비상 경보를 대신하는 것으로 취급하지 않는다.
